<h2>13.2 如何使用Mini CRT</h2>

<p>透過上面的章節，我們已經基本實現了一個可以使用的Mini CRT，它雖然小但是卻能支援大部分常用的CRT函式，使得程式可以脫離Glibc和MSVC CRT，僅依賴於Mini CRT就可以執行。而且Mini CRT還有一個驚人的特性那就是它是跨平台的，它可以執行在兩個作業系統下面。有了上面章節中的實現原理及原始碼之後，在這一節中將介紹如何使用Mini CRT。</p>

<p>一般一個CRT提供給終端使用者時往往有兩部分，一部分是CRT的庫檔案部分，用於與使用者程式進行連結，如Glibc提供了兩個版本的庫檔案：靜態Glibc庫libc.a和動態Glibc庫libc.so；MSVC CRT也提供了靜態和動態版本，libcmt.lib與msvcrt90.dll。CRT的另外一部分就是它的標頭檔，包含了使用該CRT所需要的所有常數定義、宏定義及函式宣告，通常CRT都會有很多個標頭檔。</p>

<p>Mini CRT也將以庫檔案和標頭檔的形式提供給使用者。首先我們建立一個minicrt.h的標頭檔，然後將所有相關的常數定義、宏定義，以及Mini CRT所實現的函式宣告等放在該標頭檔裡。當使用者程式使用Mini CRT時，僅需要#include “minicrt.h”即可，而無須像標準的CRT一樣，需要獨立的包含相關檔案，比如“stdio.h”、“stdlib.h”等。minicrt.h的內容如清單13-6所示。</p>

<p>清單13-6 minicrt.h</p>

<pre>#ifndef __MINI_CRT_H__
#define __MINI_CRT_H__

#ifdef __cplusplus

<p>接下來的問題是如何編譯得到庫檔案了。由於動態函式庫的實現比靜態函式庫要複雜，所以Mini CRT僅僅以靜態函式庫的形式提供給終端使用者，在Windows下它是minicrt.lib；在Linux下它是minicrt.a。在不同平台下編譯和製作庫檔案的步驟如下所示，Linux下的命令列為：</p>

<pre>$gcc -c -fno-builtin -nostdlib -fno-stack-protector entry.c malloc.c stdio.c string.c printf.c
$ar -rs minicrt.a malloc.o printf.o stdio.o string.o
</pre>

<p>這裡的<code>-fno-builtin</code>引數是指關閉GCC的內建函式功能，預設情況下GCC會把strlen、strcmp等這些常用函式展開成它內部的實現。</p>

<p><code>-nostdlib</code>表示不使用任何來自Glibc、GCC的庫檔案和啟動檔案，它包含了<code>-nostartfiles</code>這個引數。</p>

<p><code>-fno-stack-protector</code>是指關閉堆疊保護功能，最近版本的GCC會在vfprintf這樣的變長引數函式中插入堆疊保護函式，如果不關閉，我們在使用Mini CRT時會發生“__<code>stack_chk_fail</code>”函式未定義的錯誤。</p>

<p>在Windows下，Mini CRT的編譯方法如下：</p>

<pre>&gt;cl /c /DWIN32 /GS- entry.c malloc.c printf.c stdio.c string.c
&gt;lib entry.obj malloc.obj printf.obj stdio.obj string.obj /OUT:minicrt.lib
</pre>

<p>/DWIN32表示定義WIN32這個宏，這也正是在程式碼中用於區分平台的宏。</p>

<p>/GS- 表示關閉堆疊保護功能，MSVC和GCC一樣也會在不定引數中插入堆疊保護功能。不管這個功能會不會在最後連結時發生“__<code>security_cookie</code>”和“__<code>security_check_ cookie</code>”符號未定義錯誤。</p>

<p>/GS- 表示關閉堆疊保護功能，MSVC和GCC一樣也會在不定引數中插入堆疊保護功能。不管這個功能會不會在最後連結時發生“__<code>security_cookie</code>”和“__<code>security_check_ cookie</code>”符號未定義錯誤。</p>

<p>為了測試Mini CRT是否能夠正常執行，我們專門編寫了一段測試程式碼，用於測試Mini CRT的功能，如清單13-7所示。</p>

<p>清單13-7 test.c</p>

<pre>#include "minicrt.h"

int main(int argc, char* argv[])
{
    int i;
    FILE* fp;
    char** v = malloc(argc*sizeof(char*));
    for(i = 0; i &lt; argc; ++i) {
        v[i] = malloc(strlen(argv[i]) + 1);
        strcpy(v[i], argv[i]);
    }

    fp = fopen("test.txt","w");
    for(i = 0; i &lt; argc; ++i) {
        int len = strlen(v[i]);
        fwrite(&amp;len, 1, sizeof(int), fp);
        fwrite(v[i],1, len, fp);
    }
    fclose(fp);

    fp = fopen("test.txt","r");
    for(i = 0; i &lt; argc; ++i) {
        int len;
        char* buf;
        fread(&amp;len, 1, sizeof(int), fp);
        buf = malloc(len + 1);
        fread(buf, 1, len, fp);
        buf[len] = '\0';
        printf("%d %s\n", len, buf);
        free(buf);
        free(v[i]);
    }
    fclose(fp);
}
</pre>

<p>這段程式碼用到了Mini CRT中絕大部分函式，包括malloc、free、fopen、fclose、fread、fwrite、printf，並且測試了main引數。它的作用就是將main的引數字串都儲存到檔案中，然後再讀取出來，由printf顯示出來。在Linux下，可以用下面的方法編譯和執行test.c：</p>

<pre>$gcc -c -ggdb -fno-builtin -nostdlib -fno-stack-protector test.c 
$ld -static -e mini_crt_entry entry.o test.o minicrt.a –o test
$ ls -l test

$ ./test arg1 arg2 123

3 123
</pre>

<p><code>-e mini_crt_entry</code>用於指定入口函式。</p>
