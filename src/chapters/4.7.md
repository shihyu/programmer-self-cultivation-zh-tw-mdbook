<h2>4.7 BFD庫</h2>

<p>由於現代的硬體和軟體平台種類非常繁多，它們之間千差萬別，比如，硬體中CPU有8位的、16位的，一直到64位的；位元組序有大端的也有小端的；有些有MMU有些沒有；有些對訪問記憶體地址對齊有著特殊要求，比如MIPS，而有些則沒有，比如x86。軟體平台有些支援動態連結，而有些不支援；有些支援除錯，有些又不支援。這些五花八門的軟硬體平台基礎導致了每個平台都有它獨特的目的檔格式，即使同一個格式比如ELF在不同的軟硬體平台都有著不同的變種。種種差異導致編譯器和連結器很難處理不同平台之間的目的檔，特別是對於像GCC和binutils這種跨平台的工具來說，最好有一種統一的介面來處理這些不同格式之間的差異。</p>

<p>BFD庫（Binary File Descriptor library）就是這樣的一個GNU專案，它的目標就是希望透過一種統一的介面來處理不同的目的檔格式。BFD這個專案本身是binutils專案的一個子專案。BFD把目的檔抽象成一個統一的模型，比如在這個抽象的目的檔模型中，最開始有一個描述整個目的檔總體資訊的“檔案頭”，就跟我們實際的ELF檔案一樣，檔案頭後面是一係列的段，每個段都有名字、屬性和段的內容，同時還抽象了符號表、重定位表、字串表等類似的概念，使得BFD庫的程式只要透過操作這個抽象的目的檔模型就可以實現操作所有BFD支援的目的檔格式。</p>

<p>現在GCC（更具體地講是GNU 組譯器GAS， GNU Assembler）、連結器ld、偵錯程式GDB及binutils的其他工具都透過BFD庫來處理目的檔，而不是直接操作目的檔。這樣做最大的好處是將編譯器和連結器本身同具體的目的檔格式隔離開來，一旦我們需要支援一種新的目的檔格式，只需要要在BFD庫裡面新增一種格式就可以了，而不需要修改編譯器和連結器。到目前為止，BFD庫支援大約25種處理器平台，將近50種目的檔格式。</p>

<p>當我們安裝了BFD開發庫以後（在我的ubuntu下，包含BFD開發庫的軟體包的名字叫binutils-dev），我們就可以在程式中使用它。比如下面這段程式可以輸出該BFD庫所支援的所有的目的檔格式：</p>

<pre>/* target.c */
#include &lt;stdio.h&gt;
#include "bfd.h"

int main()
{
    const char** t = bfd_target_list();
    while(*t) {
        printf("%s\n", *t);
        t++;
    }
} 
</pre>

<p>編譯執行：</p>

<pre>$gcc -o target target.c –lbfd

</pre>
