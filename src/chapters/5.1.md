<h2>5.1 Windows的二進位檔案格式PE/COFF</h2>

<p>在32位Windows平台下，微軟引入了一種叫PE（Protable Executable）的可執行格式。作為Win32平台的標準執行檔格式，PE有著跟ELF一樣良好的平台擴充套件性和靈活性。PE檔案格式事實上與ELF同根同源，它們都是由COFF（Common Object File Format）格式發展而來的，更加具體地講是來源於當時著名的DEC（Digital Equipment Corporation）的VAX/VMS上的COFF檔案格式。因為當微軟開始開發Windows NT的時候，最初的成員都是來自於DEC公司的VAX/VMS小組，所以他們很自然就將原來系統上熟悉的工具和檔案格式都搬了過來，並且在此基礎上做重新設計和改動。</p>

<p>微軟將它的執行檔格式命名為“Portable Executable”，從字面意義上講是希望這個執行檔格式能夠在不同版本的Windows平台上使用，並且可以支援各種CPU。比如從Windows NT、Windows 95到Windows XP及Windows Vista，還有Windows CE都是使用PE執行檔格式。不過可惜的是Windows的PC版只支援x86的CPU，所以我們幾乎只要關注PE在x86上的各種性質就行了。</p>

<p>請注意，上面在講到PE檔案格式的時候，只是說Windows平台下的執行檔採用該格式。事實上，在Windows平台，VISUAL C++編譯器產生的目的檔仍然使用COFF格式。由於PE是COFF的一種擴充套件，所以它們的結構在很大程度上相同，甚至跟ELF檔案的基本結構也相同，都是基於段的結構。所以我們下面在討論Windows平台上的檔案結構時，目的檔預設為COFF格式，而執行檔為PE格式。但很多時候我們可以將它們統稱為PE/COFF檔案，當然我們在下文中也會對比PE與COFF在結構方面的區別之處。</p>

<p>隨著64位Windows的發布，微軟對64位Windows平台上的PE檔案結構稍微做了一些修改，這個新的檔案格式叫做PE32+。新的PE32+並沒有新增任何結構，最大的變化就是把那些原來32位的欄位變成了64位，比如檔案頭中與地址相關的欄位。絕大部分情況下，PE32+與PE的格式一致，我們可以將它看作是一般的PE檔案。</p>

<p>與ELF檔案相同，PE/COFF格式也是採用了那種基於段的格式。一個段可以包含程式碼、資料或其他資訊，在PE/COFF檔案中，至少包含一個程式碼段，這個程式碼段的名字往往叫做“.code”，資料段叫做“.data”。不同的編譯器產生的目的檔的段名不同，VISUAL C++使用“.code”和“.data”，而Borland的編譯器使用“CODE”，“DATA”。也就是說跟ELF一樣，段名只有提示性作用，並沒有實際意義。當然，如果使用連結指令碼來控制連結，段名可能會起到一定的作用。</p>

<p>跟ELF一樣，PE中也允許程式設計師將變數或函式放到自定義的段。在GCC中我們使用“__<code>attribute__((section(“name”)))”</code>擴充套件屬性，在VISUAL C++中可以使用<code>“#pragma</code>”編譯器指示。比如下面這個語句：</p>

<pre>#pragma data_seg("FOO")
int global = 1;
#pragma data_seg(".data")
</pre>

<p>就表示把所有全域性變數“global”放到“FOO”段裡面去，然後再使用<code>“#pragram</code>”將這個編譯器指示換回來，恢複到“.data”，否則，任何全域性變數和靜態變數都會被放到“FOO”段。</p>
