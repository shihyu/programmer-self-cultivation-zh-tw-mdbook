<h2>5.5 大家都有符號表</h2>

<p>“SimpleSection.txt”的最後部分是COFF符號表（Symbol table），COFF檔案的符號表包含的內容幾乎跟ELF檔案的符號表一樣，主要就是符號名、符號的型別、所在的位置。我們把“SimpleSection.txt”關於符號表的輸出摘錄如下：</p>

<pre>COFF SYMBOL TABLE
000 006DC627 ABS    notype      Static        | @comp.id
001 00000001 ABS    notype      Static      | @feat.00
002 00000000 SECT1  notype      Static      | .drectve
    Section length   18, #relocs  0, #linenums  0, checksum     0
004 00000000 SECT2  notype      Static      | .debug$S
    Section length   86, #relocs  0, #linenums  0, checksum     0
006 00000004 UNDEF  notype      External    | _global_uninit_var
007 00000000 SECT3  notype      Static      | .data
    Section length    C, #relocs  0, #linenums  0, checksum AC5AB941
009 00000000 SECT3  notype      External    | _global_init_var
00A 00000004 SECT3  notype      Static      | $SG594

00C 00000000 SECT4  notype      Static      | .text
    Section length   4E, #relocs    5, #linenums  0, checksum CC61DB94

    Section length    4, #relocs  0, #linenums  0, checksum     0
013 00000000 SECT5  notype      Static    | ?static_var2@?1??main@@9@9 ('main'::'2'::static_var2)
</pre>

<p>在輸出結果的最左列是符號的編號，也是符號在符號表中的下標。接著是符號的大小，即符號所表示的物件所佔用的空間。第三列是符號所在的位置，ABS（Absolute）表示符號是個絕對值，即一個常量，它不存在於任何段中；SECT1（Section #1）表示符號所表示的物件定義在本COFF檔案的第一個段中，即本例中的“.drectve”段；UNDEF（Undefined）表示符號是未定義的，即這個符號被定義在其他目的檔。第四列是符號型別，可以看到對於C語言的符號，COFF只區分了兩種，一種是變數和其他符號，類行為notype，另外一種是函式，型別為 notype ()，這個符號型別值可以用於其他一些需要強符號型別的語言或系統中，可以給連結器更多的資訊來識別符號的型別。第五列是符號的可見範圍，Static表示符號是區域性變數，只有目的檔內部是可見的；External表示符號是全域性變數，可以被其他目的檔引用。最後一列是符號名，對於不需要修飾的符號名，“dumpbin”直接輸出原始的符號名；對於那些經過修飾的符號名，它會把修飾前和修飾後的名字都列印出來，後面括號裡面的就是未修飾的符號名。</p>

<p>從符號表的dump輸出資訊中，我們可以看到“_global_init_varabal”這個符號位於Section #3，即“.data”段，它的長度是4個位元組，可見範圍是全域性。另外還有一個為$SG574的符號，其實它表示的是程式中的那個“%d\n”字串常量。因為程式中要引用到這個字串常量，而該字串常量又沒有名字，所以編譯器自動為它生成了一個名字，並且作為符號放在符號表裡面，可以看到這個符號對外部是不可見的。可以看到，ELF檔案中並沒有為字串常量自動生成的符號，另外所有的段名都是一個符號，“dumpbin”如果碰到某個符號是一個段的段名，那麼它還會解析該符號所表示的段的基本屬性，每個段名符號後面緊跟著一行就是段的基本屬性，分別是段長度、重定位數、行號數和校驗和。</p>
