<h2>6.5 Linux核心載入ELF過程簡介</h2>

<p>當我們在Linux系統的bash下輸入一個命令執行某個ELF程式時，Linux系統是怎樣載入這個ELF檔案並且執行它的呢？</p>

<p>首先在使用者層面，bash程式會呼叫fork()系統呼叫建立一個新的程式，然後新的程式呼叫<code>execve()</code>系統呼叫執行指定的ELF檔案，原先的bash程式繼續返回等待剛才啟動的新程式結束，然後繼續等待使用者輸入命令。<code>execve()</code>系統呼叫被定義在unistd.h，它的原型如下：</p>

<pre>int execve(const char *filename, char *const argv[], char *const envp[]);</pre>

<p>它的三個引數分別是被執行的程式檔名、執行引數和環境變數。Glibc對<code>execvp()</code>系統呼叫進行了包裝，提供了<code>execl()、execlp()、execle()、execv()</code>和<code>execvp()</code>等5個不同形式的exec係列API，它們只是在呼叫的引數形式上有所區別，但最終都會呼叫到<code>execve()</code>這個系統中。下面是一個簡單的使用<code>fork()</code>和<code>execlp()</code>實現的minibash：</p>

<pre>#include &lt;stdio.h&gt;
#include &lt;sys/types.h&gt;
#include &lt;unistd.h&gt;

int main()
{
    char buf[1024] = {0};
    pid_t pid;
    while(1) {
        printf("minibash$");
        scanf("%s", buf);
        pid = fork();
        if(pid == 0) {
            if(execlp(buf, 0 ) &lt; 0) {
                printf("exec error\n");
            }
        } else if(pid &gt; 0){
            int status;
            waitpid(pid,&amp;status,0);
        } else {
            printf("fork error %d\n",pid);
        }
}
    return 0;
}
</pre>

<p>在進入<code>execve()</code>系統呼叫之後，Linux核心就開始進行真正的載入工作。在核心中，<code>execve()</code>系統呼叫相應的入口是<code>sys_execve()，</code>它被定義在arch\i386\kernel\Process.c。<code>sys_execve()</code>進行一些引數的檢查複製之後，呼叫<code>do_execve()。do_execve()</code>會首先查詢被執行的檔案，如果找到檔案，則讀取檔案的前128個位元組。為什麼要這麼做呢？因為我們知道，Linux支援的執行檔不止ELF一種，還有a.out、Java程式和以“#!”開始的指令碼程式。Linux還可以支援更多的執行檔格式，如果某一天Linux須支援Windows PE的執行檔格式，那麼我們可以編寫一個支援PE載入的核心模組來實現Linux對PE檔案的支援。這裡<code>do_execve()</code>讀取檔案的前128個位元組的目的是判斷檔案的格式，每種執行檔的格式的開頭幾個位元組都是很特殊的，特別是開頭4個位元組，常常被稱做魔數（Magic Number），透過對魔數的判斷可以確定檔案的格式和型別。比如ELF的執行檔格式的頭4個位元組為0x7F、’e’、’l’、’f’；而Java的執行檔格式的頭4個位元組為’c’、’a’、’f’、’e’；如果被執行的是Shell指令碼或perl、python等這種解釋型語言的指令碼，那麼它的第一行往往是“#!/bin/sh”或“#!/usr/bin/perl”或“#!/usr/bin/python”，這時候前兩個位元組’#’和’!’就構成了魔數，系統一旦判斷到這兩個位元組，就對後面的字串進行解析，以確定具體的解釋程式的路徑。</p>

<p>當<code>do_execve()</code>讀取了這128個位元組的檔案頭部之後，然後呼叫<code>search_binary_handle()</code>去搜尋和匹配合適的執行檔載入處理過程。Linux中所有被支援的執行檔格式都有相應的載入處理過程，<code>search_binary_handle()</code>會透過判斷檔案頭部的魔數確定檔案的格式，並且呼叫相應的載入處理過程。比如ELF執行檔的載入處理過程叫做<code>load_elf_binary()；</code>a.out執行檔的載入處理過程叫做<code>load_aout_binary()；</code>而載入可執行指令碼程式的處理過程叫做<code>load_script()。</code>這裡我們只關心ELF執行檔的載入，<code>load_elf_binary()</code>被定義在fs/Binfmt_elf.c，這個函式的程式碼比較長，它的主要步驟是：</p>

<p>（1）檢查ELF執行檔格式的有效性，比如魔數、程式頭表中段（Segment）的數量。</p>

<p>（2）尋找動態連結的“.interp”段，設定動態連結器路徑（與動態連結有關，具體請參考第9章）。</p>

<p>（3）根據ELF執行檔的程式頭表的描述，對ELF檔案進行對映，比如程式碼、資料、只讀資料。</p>

<p>（4）初始化ELF程式環境，比如程式啟動時EDX暫存器的地址應該是DT_FINI的地址（參照動態連結）。</p>

<p>（5）將系統呼叫的返回地址修改成ELF執行檔的入口點，這個入口點取決於程式的連結方式，對於靜態連結的ELF執行檔，這個程式入口就是ELF檔案的檔案頭中<code>e_entry</code>所指的地址；對於動態連結的ELF執行檔，程式入口點是動態連結器。</p>

<p>當<code>load_elf_binary()</code>執行完畢，返回至<code>do_execve()</code>再返回至<code>sys_execve()</code>時，上面的第5步中已經把系統呼叫的返回地址改成了被載入的ELF程式的入口地址了。所以當<code>sys_execve()</code>系統呼叫從核心態返回到使用者態時，EIP暫存器直接跳轉到了ELF程式的入口地址，於是新的程式開始執行，ELF執行檔載入完成。</p>
